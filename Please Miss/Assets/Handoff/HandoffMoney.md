# Handoff Money — Система Points (Денег)

Статус: **спецификация / план работ**. Код ещё не написан.
Проект: Please Miss (Unity + NGO).

---

## 1. Общее описание

Вводим валюту — **Points (очки/деньги)**. Очки зарабатываются в игре, тратятся в магазине в
главном меню, предметы из локального инвентаря игрок берёт с собой в матч и продаёт за очки
при добегании до победной зоны.

### Стартовый баланс
- Каждый игрок начинает с **500 points**.

---

## 2. Механика очков (ключевые цифры)

| Событие | Начисление |
|---|---|
| Раннер добежал до победной зоны | **300** фикс. + **2 очка за каждую оставшуюся секунду таймера** (чем быстрее — тем больше) |
| Продажа предметов при добегании | Сумма за каждый предмет (см. п.3) |
| Снайпер убил бегуна | **+50** за убийство + бонус за зону попадания (см. ниже) |
| (Позже) Вылечил другого игрока | Бонусные очки за помощь (величину уточнить) |
| (Позже) Близко увернулся от пули | Бонусные очки (величину уточнить) |

### Бонусы снайпера за зону попадания
- **Голова** — очки за убийство **×2** (т.е. 50 × 2 = 100).
- **Рука** — очки за убийство **×1.2** (т.е. 50 × 1.2 = 60).
- **Тело** — бонуса нет, просто **+50**.
- ⚠️ В ТЗ опечатка («x2 если убил в руку … если в руку то x1.2») — в тексте принято
  «голова ×2, рука ×1.2». **Подтвердить перед реализацией.**

### Условия начисления
- Раннер **не добежал** (умер): очки за добегание НЕ начисляются, но бонусы за действия
  (лечение, уклонение и т.п.) начисляются.
- Раннер **добежал**: предметы продаются + 300 + бонус за время + бонусы за действия.

## 3. Предметы: покупка, инвентарь, продажа

### Определение предмета (новый ScriptableObject, например `Assets/Scripts/Money/ItemDefinition.cs`)
Поля:
- `string ItemId`
- `string DisplayName`
- `Sprite Icon` (иконка для панельки бонуса и магазина)
- `int BuyPrice` — цена покупки в магазине («сколько стоит»)
- `int SellPrice` — цена продажи («за сколько продаётся», должна быть < BuyPrice)
- `GameObject WorldPrefab` — предмет, спавнящийся в мире (переиспользовать `PickableItem` / `WorldDropPrefab`)
- (опционально) `int MaxStack` для будущих стаков

### Локальный инвентарь игрока (вне сессии)
- Хранится локально на клиенте (PlayerPrefs/JSON профиль — см. «Открытые вопросы»).
- Набор записей: `ItemId + количество`.
- В **лобби** игрок выбирает, какие предметы взять с собой в игру: **0–2** (уточнить, возможно 3).

### Взятие предметов в игру
- Выбранные предметы спавнятся у игрока (или в мире рядом со спавном) как `PickableItem`.
- Каждому спавну проставляется **владелец** (`ulong ownerClientId` / `OwnerPlayerId`) — см. п.4.

### Продажа при добегании
- Раннер добегает до победной зоны → все предметы из его инвентаря продаются:
  - предмет **свой** (владелец = сам игрок) → начисляется **BuyPrice**;
  - предмет **чужой** (найден на локации / подобран у другого игрока) → начисляется **SellPrice**.
- Сумма добавляется к балансу раннера.

## 4. Владение предметами

Нужна проверка «чей предмет». Предлагаемая схема:

- На сетевом предмете (`PickableItem` / новый `NetworkItem`) — поле
  `NetworkVariable<ulong> OwnerClientId` (0 / ulong.MaxValue = ничей).
- При спавне из инвентаря → `OwnerClientId = владелец инвентаря`.
- Предметы, лежащие на локации по умолчанию → ничей (`0`).
- При подборе предмета игроком — **владение НЕ меняется** (остаётся исходный владелец),
  чтобы при продаже можно было определить «свой/чужой».
- В инвентаре игрока (внутри матча) на слотах хранить ссылку на `OwnerClientId` предмета
  (сейчас `Inventory` хранит только `string itemName` — расширить модель слота, см. п.8).
- При продаже: `OwnerClientId == сам игрок → BuyPrice`, иначе `→ SellPrice`.

## 5. Баланс игрока

Новый компонент (например `Assets/Scripts/Money/PlayerPoints.cs : NetworkBehaviour`) на PlayerObject:
- `NetworkVariable<int> Points` (стартовое 500).

- Точки начисления: при `RunnerWins` для раннера, при убийстве для снайпера (см. п.6).

## 6. Начисление очков: точки интеграции (существующий код)

### Раннер добежал
- `GameManager.RunnerWins()` (`Assets/Scripts/Game/GameManager.cs:463`) — вызывается при
  победе раннеров. Здесь (на сервере) для каждого добежавшего раннера:
  - 300 + `2 * floor(GameTimeRemaining.Value)` (таймер: `GameManager.cs:47`);
  - продажа предметов инвентаря по п.3 (нужно знать, какие раннеры реально добежали —
    уточнить механизм фиксации «добежал»: триггер победной зоны / `LocalRunnerFinished`).
- `GameTimeRemaining.Value` — оставшееся время раунда (секунды).

### Снайпер убил бегуна
- Уже есть: `GameManager.NotifySniperKill(...)` (`GameManager.cs:250`) — ловит смерть раннера,
  хранит `lastRunnerDamage` и `lastRunnerZone` (`GameManager.cs:233-237`), шлёт
  `SniperKillRecordedClientRpc` с `zoneName` и `survivedTime`.
- Зоны попадания: `PlayerHealth.HitZones` / `FindHitZone` (`PlayerHealth.cs:228`) — зоны
  `PlayerHitZone` с именами (Head/Arm/Body). Проверить текущие имена зон в префабе.
- Здесь же начислять снайперу 50 × множитель зоны и фиксировать запись для панельки.

### Раннер умер (не добежал)
- `GameManager.OnRunnerDeathStateChanged` (`GameManager.cs:239`) — бонусы за действия
  начислять и при смерти.

## 7. UI

### 7.1 Магазин в MainMenu (вкладка «Магазин»)
- Новое окно в `MainMenuUI` (`Assets/Scripts/UI/MainMenuUI.cs`) — вкладка/кнопка «Shop».
- Список `ItemDefinition`: иконка, название, цена покупки, кнопка «Купить».
- Покупка: `SpendPoints(BuyPrice)` из локального баланса → предмет в локальный инвентарь.
- Показывать текущий баланс.

### 7.2 Инвентарь в лобби
- `LobbyManager` (`Assets/Scripts/Game/LobbyManager.cs`) или UI-окно в лобби.
- Список локального инвентаря с количеством.
- Выбор предметов «взять с собой»: **0–2 слота** (уточнить, может 3).
- Ограничение количества и валидация перед стартом матча.

### 7.3 Панельки бонусов в конце игры
- **`RunnerEndPanelUI`** (`Assets/Scripts/UI/RunnerEndPanelUI.cs`): добавить **контейнер**
  (например `RectTransform` + `VerticalLayoutGroup`), в который спавнятся панельки.
- **`SniperEndPanelUI`** (`Assets/Scripts/UI/SniperEndPanelUI.cs`): то же самое.
- Новый префаб **`PointsBonusPanel`**: `[Текст действия] [Иконка] [Текст очков]`.
- Контейнер в обоих панелях: пустой по умолчанию, панельки наполняются перед показом.

### 7.4 Какие панельки спавнятся
Раннер:
- «Очки за то, что добежал до конца» (только если добежал);
- «Вылечил игрока» (за каждое лечение — отдельная панелька);
- «Близко увернулся от пули» (за каждый случай);
- продажа предметов (опционально отдельной панелькой: «Продано предметов: N (+X)»).

Снайпер:
- «Убил игрока в голову» (за каждое — отдельная панелька);
- «Убил игрока в тело» и т.п. — по зоне попадания;
- на каждой панельке сумма очков за это действие.

### 7.5 Доставка данных панелек на клиент
- Начисление выполняется на сервере → список записей
  `(actionId/локальный текст, iconRef, points)` отправлять клиенту **ClientRpc** в момент
  конца игры (или по мере событий, накапливая на клиенте). Рекомендуется: накапливать
  на сервере у `PlayerPoints`, отправить одним RPC при `Ended`.

## 9. План реализации (фазы)

1. **Баланс**: `PlayerPoints` (NetworkVariable, старт 500, Add/Spend), UI-отображение в матче.
2. **Данные предметов**: `ItemDefinition` ScriptableObject (BuyPrice/SellPrice/Icon), каталог.
3. **Локальный профиль**: хранение баланса + инвентаря между сессиями (PlayerPrefs/JSON).
4. **Магазин** в MainMenu: список, покупка, списание очков.
5. **Инвентарь в лобби**: выбор 0–2(3) предметов, спавн их в матче с владельцем.
6. **Владение**: `OwnerClientId` на предмете и в слоте инвентаря.
7. **Продажа при добегании**: начисление BuyPrice/SellPrice + фикс. сумма + бонус за время.
8. **Убийства снайпера**: 50 + множитель зоны (Head ×2, Arm ×1.2, Body 50).
9. **Панельки бонусов**: префаб `PointsBonusPanel`, контейнеры в обоих EndPanel, ClientRpc данных.
10. **Позже**: аптечки (очки за лечение), уклонение от пуль.

- Не менять текущую механику дропа предметов при смерти/дисконнекте (`NetworkInventorySync`) —
  она работает; привязывать к ней только владение.

  переиспользовать для панелек снайпера.
- Всё начисление — только на сервере; клиенты только отображают.
- Таймер раунда: `GameManager.GameTimeRemaining` (float, секунды) — для бонуса «2 очка/сек».
